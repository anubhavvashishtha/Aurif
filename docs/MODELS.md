# Models

Aurif uses two model paths.

- **Text** stays on a Meta model. `META_API_KEY` and `MODEL_API_KEY` are **Meta Model API** keys for `https://api.meta.ai/v1` and **Muse Spark 1.3** (`muse-spark-1.3`). They are not Llama API keys. Llama API is retired and is not called. `LLM_PROVIDER=meta` forces that host (the key stays empty, and health shows misconfigured, when no Meta key is set). `LLM_PROVIDER=baseten` forces Baseten **Muse Spark Open** (`BASETEN_MODEL`, default `meta-models/muse-spark-open-1026`) at `https://inference.baseten.co/v1` even if a Meta key is set. When `LLM_PROVIDER` is unset, a Meta key selects the Meta Model API and otherwise `BASETEN_API_KEY` selects Baseten. `META_LLM_MODEL` overrides `META_MODEL` on the Meta path only. It does not replace `BASETEN_MODEL` when `LLM_PROVIDER` is unset and only `BASETEN_API_KEY` is set. `LLM_FALLBACK_PROVIDER=baseten` retries one failed Meta text call on Baseten when `BASETEN_API_KEY` is set; unset means no fallback. Handshake risk, the policy co-pilot, activity summaries, and Muse chat all use this path. A non-Meta id in `BASETEN_MODEL`, `META_MODEL`, `META_LLM_MODEL`, or the agent chat model is refused and does not call the host.
- **Draw-CAPTCHA vision** is separate and does not inherit the text model. Code default on Meta is **Muse Spark 1.3** (`muse-spark-1.3`) at `https://api.meta.ai/v1`. Override with `META_VISION_MODEL` — the demo `.env.example` sets **`muse-wonder-1.0`** (Muse Wonder) for CAPTCHA sketches. Without a Meta key, vision uses Baseten **Muse Spark Open** (`meta-models/muse-spark-open-1026`) with `BASETEN_API_KEY`. `VISION_PROVIDER` (case-insensitive) chooses the host: `meta` or `baseten`. When it is unset, an explicit `VISION_BASE_URL` or `META_VISION_BASE_URL` keeps the custom `VISION_*` chain. Otherwise a Meta key selects the Meta vision model above. Otherwise Baseten Muse Spark Open. A non-Meta model id is refused for vision and is never labelled Meta.
- `python app.py` prints the active text and vision provider, model, label, family, and base URL at startup, plus whether the key is set or missing (the key itself is not printed). The vision line also names the fallback provider and model when one is configured, or `fallback=unset` when none is.

`VISION_FALLBACK_PROVIDER` is empty unless you set it. The only supported value is `baseten`. When the primary vision host is Meta, a 401, 403, 404, model-not-found, 429, 5xx, or connection error retries that host once, inside the same vision time budget. A read timeout, an unreadable reply, and a valid non-match do not switch. Baseten fallback needs `BASETEN_API_KEY`. When `VISION_FALLBACK_PROVIDER` is unset, `VISION_FALLBACK_MODEL` (also empty by default) still retries once, and only on 401, 403, 404, or model-not-found. `VISION_FALLBACK_BASE_URL` and `VISION_FALLBACK_API_KEY` default to Baseten for that model retry. `VISION_FALLBACK_PROVIDER` wins if both are set. Setting it disables `VISION_FALLBACK_MODEL` even when the primary is not Meta, so that primary does not retry the model fallback either. The verify response names the model that actually judged.

A 401, 403, 404, or model-not-found is logged and stored on the vision side of `GET /api/health` and `GET /api/ai/models` as `vision model <id>: 403 forbidden, check Meta Model API model access or slug` (the host name follows the provider: Meta Model API or Baseten). The line names the provider and the model. It never includes the key or the CAPTCHA answer. A successful fallback leaves that primary error in `vision.last_error` while `vision.last_ok` stays true.

Health is per model. `text` and `vision` each have `degraded` and `last_error`, plus `fallback` (`provider`, `model`, `label`, or null). Text `fallback` is the Baseten card only when `LLM_FALLBACK_PROVIDER=baseten` and `BASETEN_API_KEY` are set. Vision `fallback` is the public card of `VISION_FALLBACK_PROVIDER` when that is set, otherwise the public card of `VISION_FALLBACK_MODEL` when that var is set. A successful text fallback keeps `text.last_ok` true and leaves the Meta error in `text.last_error`. If that Baseten attempt also fails, `text.last_error` stays the primary error and `text.fallback_error` is the Baseten failure. A text 401 or 403 is `key rejected by Meta (401 unauthorized), check the key` (403 says `403 forbidden`; the host name follows the provider). `model key missing or provider misconfigured` is only when the key or base URL is absent. `GET /api/health` returns **200** when text is up, including a vision-only outage: `degraded` is true and `partial` is true. That is the same 200-plus-degraded shape the handshake, policy, and activity routes already use for a partial outage. **503** is only when text is down (`ok` is false). Health and `GET /api/ai/models` expose per-side `degraded` / `last_error`; the dashboard no longer shows a global model-status banner. A vision-only failure does not say handshakes left the model.

## Timeouts and outages

| Variable | Default | Meaning |
|----------|---------|---------|
| `META_TIMEOUT_SECONDS` | `8` | Text call budget, in seconds (clamped to 0.2–60). Also used for vision when both vision timeout vars are unset |
| `META_VISION_TIMEOUT_SECONDS` | `15` | Vision call budget. Used when `VISION_TIMEOUT_SECONDS` is unset |
| `VISION_TIMEOUT_SECONDS` | unset | Optional vision budget. Wins over `META_VISION_TIMEOUT_SECONDS` when set |
| `META_MAX_RETRIES` | `1` | Extra attempts after the first, capped at 2. Read timeouts are not retried. Connection failures and HTTP 408/429/500/502/503/504 are |

Handshake risk scoring, when the model errors or times out, uses a keyword rule instead of hanging or stripping `act` from every agent. A clear shopping purpose can still receive `act`. Scraping, bypass, resale, and vague purposes stay view-only. The handshake body says `purpose_risk.source` is `rules`, `degraded` is true, and `fallback` is `keyword_rules`. The score also carries the configured text model (`id`, `provider`, `label`, `family`, `powered_by`) and `latency_ms`. The agent-facing `reason` does not include env var names. A separate `warning` says the model was unavailable.

Policy propose and activity summary use the same text client and the same timeout. If that call errors or times out, policy propose returns HTTP 200 with a keyword-rules draft (`fallback` `keyword_rules`) and activity summary returns HTTP 200 with the counted brief (`fallback` `activity_counts`). Both set `source` to `rules` and `degraded` to true. Neither path writes policy. The owner applies a proposal with a separate request. When the model text is used, the dashboard shows `Powered by Meta <model>` plus latency. A fallback credit says it is a fallback and does not name that line as Meta or show `0 ms`. Every Muse text call (handshake, browse polish, policy co-pilot, activity summary, owner page report) sends `reasoning_effort` `low` on hosts other than `api.meta.ai`, plus the open-weight `chat_template_kwargs` form. A 400 on that field is retried once without it. `api.meta.ai` sends top-level `reasoning_effort` `low` and does not send `chat_template_kwargs`. A 400 whose message mentions `reasoning_effort` is retried once without that field. `none` is sent as `low`. The text timeout stays 8 seconds. Only `message.content` is the reply. A response that is only reasoning is logged as `model returned only reasoning` and falls back; that path does not log `model unavailable (model request failed)`. On Baseten the output budgets are handshake 2048, browse polish 1024, owner page report 1024, activity summary 2048, and policy co-pilot 2500. Activity summaries are given the counts as structured facts. A reply is kept when every count it states matches those facts (digits or words, any order). Digits inside version strings and agent ids are not counts, and a number does not bind across a sentence. A changed or invented count is discarded. The reject reason and the offending phrase are logged at warning, and the raw reply is logged at debug with secrets removed.

CAPTCHA, when vision is unavailable: a typed `answer` matching the challenge, or a non-blank jpeg, png, gif, or webp sketch from the drawing pad, opens the **human storefront only**. The response is `degraded: true` with `method` `typed_fallback` or `ink_fallback`, and it does not grant agent `act`. A blank image gets HTTP 403 with `fallback` instructions. That object has no `target` field, and the prompt does not repeat the characters. A working vision model that rejects a drawing (wrong characters, a blank pad, a scribble, or a speck too small to be a character) does not take this path. The reject `error` is `drawing did not match` and does not echo the model reason or the expected characters.

The vision judge is strict. `match` must be true, the strokes must be hand-drawn, and `read_as` must be the requested characters. A correct `read_as` does not override `match: false`. The string `"false"` does not count as true. A reason that starts with blank, scribble, wrong, or a similar rejection, or a confidence below 0.8, is a rejection. A blank pad is rejected locally with reason `blank`, and a drawing whose ink is only a few pixels, or whose stroke is shorter than 12 pixels on the long side, is rejected locally with reason `drawing too small`. Neither calls the model.

## Why these hosts

| Option | Why it was or was not the default |
|--------|-----------------------------------|
| Meta Model API, `muse-spark-1.3` | **Text default when `LLM_PROVIDER=meta`, or when `LLM_PROVIDER` is unset and `MODEL_API_KEY` or `META_API_KEY` is set.** Also the **code default for vision** on that key (`META_VISION_MODEL` unset). Demo env often sets `META_VISION_MODEL=muse-wonder-1.0` for draw-CAPTCHA. First-party Meta inference for handshake risk, policy, activity, Muse chat, and CAPTCHA vision. These keys are Meta Model API keys, not Llama API keys. |
| Baseten `meta-models/muse-spark-open-1026` | **Text host when `LLM_PROVIDER=baseten`, and the text default when `LLM_PROVIDER` is unset and only `BASETEN_API_KEY` is set.** Also **vision** when no Meta key is set, when `VISION_PROVIDER=baseten`, or when the custom `VISION_*` chain resolves to Baseten. Optional `LLM_FALLBACK_PROVIDER=baseten` retries one Meta text failure. Optional `VISION_FALLBACK_PROVIDER=baseten` retries one Meta vision failure. Same Meta weights the demo already calls. The public slug `meta-models/muse-spark-open` has 403'd on some participant keys, so the dated id stays the default. |
| Another vision model (SAM 3.1, Muse, Llama) | Set `VISION_BASE_URL` (or `META_VISION_BASE_URL`). That explicit host wins over the Meta default. Pair it with `VISION_MODEL` and `VISION_API_KEY` (or the matching `META_VISION_*` name when `VISION_*` is unset). No code change. A Meta model id is labelled Meta. A non-Meta id is refused. |
| `VISION_FALLBACK_PROVIDER` | Optional, empty by default. Set to `baseten` when the primary vision host is Meta. One retry on access errors, 429, 5xx, or a dropped connection. Not on a read timeout or a readable non-match. |
| `VISION_FALLBACK_MODEL` | Optional, empty by default. Ignored whenever `VISION_FALLBACK_PROVIDER` is set, including when the primary is not Meta. One retry after 401/403/404 or model-not-found. Example: `meta-models/muse-spark-open-1026` on Baseten. |

`META_REASONING_EFFORT` defaults to `low` on `api.meta.ai` only. Muse Spark always reasons, and `none` is sent as `low` because the API rejects `none`. `api.meta.ai` does not receive `chat_template_kwargs`. A 400 that mentions `reasoning_effort` is retried once without it. Every other Muse text call sends `reasoning_effort` `low` and `chat_template_kwargs.reasoning_effort` `low`, and retries once without those fields on HTTP 400. Temperature is sent alone (Meta rejects temperature together with `top_p`). On the Meta Model API the output budget is raised to at least 768 tokens so reasoning does not consume a short `max_tokens` before the answer. `max_tokens` stays the request field (Baseten needs it; Meta accepts it as an alias of `max_completion_tokens`). Baseten sends the requested budget: handshake 2048, browse polish 1024, owner page report 1024, activity summary 2048, policy co-pilot 2500. The answer is `message.content` only. Reasoning text is never the reply.

## Environment

Names only; do not commit secrets.

Text uses one of the Meta or Baseten keys below. `MODEL_API_KEY` and `META_API_KEY` are Meta Model API keys (`api.meta.ai`, `muse-spark-1.3`), not Llama API keys. Vision uses the Meta key when that key is set, unless `VISION_PROVIDER=baseten` or an explicit vision base URL selects another host. Otherwise it uses `BASETEN_API_KEY` unless a vision key is configured.

| Variable | Required | Default |
|----------|----------|---------|
| `MODEL_API_KEY` | one of this, `META_API_KEY`, or `BASETEN_API_KEY` for text | — |
| `META_API_KEY` | alias of `MODEL_API_KEY`; wins if both Meta keys are set. Meta Model API key, not a Llama API key | — |
| `BASETEN_API_KEY` | text when no Meta key is set, or when `LLM_PROVIDER=baseten`; vision on the Baseten path and for `VISION_FALLBACK_*` | — |
| `BASETEN_MODEL` | no | `meta-models/muse-spark-open-1026` (text on the Baseten path only) |
| `LLM_PROVIDER` | no | unset. `meta` or `baseten`. Anything else is ignored. Unset: Meta when a Meta key is set, else Baseten |
| `LLM_FALLBACK_PROVIDER` | no | unset (no text fallback). `baseten` retries a Meta 401/403/404/429/5xx or connection error once |
| `META_LLM_MODEL` | no | unset. On the Meta text path, wins over `META_MODEL`. Ignored when the unset path is Baseten. Example `muse-spark-1.3` |
| `META_PROVIDER` | no | `meta`, or `baseten` when the Baseten key is the text host |
| `META_BASE_URL` | no | `https://api.meta.ai/v1`, or `https://inference.baseten.co/v1` on the text Baseten path. Not applied when `LLM_PROVIDER=baseten` |
| `META_MODEL` | no | `muse-spark-1.3`, or `BASETEN_MODEL` on the text Baseten path. `META_LLM_MODEL` wins when both are set |
| `VISION_MODEL` | no | on the Meta path, used only when it is a Meta-family id and `META_VISION_MODEL` is unset. On the Baseten path, `meta-models/muse-spark-open-1026` when unset |
| `VISION_BASE_URL` | no | unset. When set, this host wins over the Meta default. Ignored when `VISION_PROVIDER=meta` |
| `VISION_API_KEY` | no | see key order below |
| `VISION_PROVIDER` | no | unset, which selects Meta when a Meta key is set. `meta` or `baseten`. Any other value falls through to the custom chain or Meta/Baseten defaults |
| `META_VISION_MODEL` | no | Meta vision model override. Code default `muse-spark-1.3`; demo example `muse-wonder-1.0` |
| `META_VISION_BASE_URL` | no | overrides `https://api.meta.ai/v1` on the Meta path. On the custom path, used when `VISION_BASE_URL` is unset |
| `META_VISION_API_KEY` | no | used only when `VISION_API_KEY` is unset, on the custom or Baseten path |
| `META_VISION_PROVIDER` | no | label used only when `VISION_PROVIDER` is unset, on the custom or Baseten path |
| `META_REASONING_EFFORT` | no | `low` (Meta Model API only) |
| `META_TIMEOUT_SECONDS` | no | `8` |
| `META_VISION_TIMEOUT_SECONDS` | no | `15` |
| `VISION_TIMEOUT_SECONDS` | no | unset; falls through to `META_VISION_TIMEOUT_SECONDS` |
| `META_MAX_RETRIES` | no | `1` |
| `VISION_FALLBACK_PROVIDER` | no | unset (no provider fallback). `baseten` when primary vision is Meta |
| `VISION_FALLBACK_MODEL` | no | unset (no model fallback). Disabled whenever `VISION_FALLBACK_PROVIDER` is set, including for a non-Meta primary |
| `VISION_FALLBACK_BASE_URL` | no | `https://inference.baseten.co/v1` for the model fallback |
| `VISION_FALLBACK_API_KEY` | no | `BASETEN_API_KEY` for the model fallback |

Vision host order when `VISION_PROVIDER` is unset: an explicit `VISION_BASE_URL` or `META_VISION_BASE_URL`, otherwise Muse Spark 1.3 when `META_API_KEY` or `MODEL_API_KEY` is set, otherwise Baseten Muse Spark Open. `VISION_PROVIDER=meta` uses `https://api.meta.ai/v1` (`META_VISION_BASE_URL` may override; `VISION_BASE_URL` does not) and the key `VISION_API_KEY`, then `META_API_KEY`, then `MODEL_API_KEY`. `VISION_PROVIDER=baseten` uses the `VISION_*` / `META_VISION_*` chain and ignores the Meta default. The Meta key is sent only when the vision URL uses scheme `https` and hostname `api.meta.ai` exactly. A path, a suffix domain, or userinfo that merely contains that name does not. A custom host, including one whose model id is Meta-family, gets `BASETEN_API_KEY` or no key. A Baseten key is never sent to `api.meta.ai`. When Meta is chosen because a Meta key is set and `VISION_PROVIDER` is unset, that Meta key is used and `VISION_API_KEY` is not. `VISION_API_KEY` wins only when `VISION_PROVIDER=meta`.

A non-Meta id in `BASETEN_MODEL`, `META_MODEL`, `META_LLM_MODEL`, or `VISION_MODEL` is refused for text or vision and does not call the host.

An existing `.env` with only `BASETEN_API_KEY` keeps text and draw-CAPTCHA vision on Muse Spark Open. Adding `MODEL_API_KEY` or `META_API_KEY` switches text and vision to Muse Spark 1.3 on the Meta Model API. Set `VISION_PROVIDER=baseten` to keep vision on Baseten after adding a Meta key. `LLM_PROVIDER=baseten` keeps text on Baseten even after a Meta key is added. `LLM_FALLBACK_PROVIDER` does not change the primary host.

## Audit

Searched `server/`. No other chat-completions client, SDK, or HTTP call to an LLM host. `server/agent_gate.py` lists the substring `anthropic` as a bot user-agent to block. That is not a model call.

The dashboard reads `GET /api/ai/models` as `models[]` and `current` (text: `id`, `label`, `provider`, `default`) plus a separate `vision` card and `health`. Policy propose, activity summary, and agent chat still return the text `model`. A rejected drawing returns a generic `error` (`drawing did not match`), `verdict` (including `model`, `provider`, `label`, `family`, `powered_by`; `read_as` is blank when it repeats the answer), and `agent_access`. When vision is down, human verify can return `degraded`, `method`, and `warning` instead of failing closed. The blank-drawing `fallback` prompt does not include the answer. `providers.text` and `providers.vision` are separate. `providers.baseten.base_url` remains for the optional Baseten host. `GET /api/health` returns 200 with `partial: true` when vision is down and text is up, and 503 when text is down. `GET /api/public/gate` still returns the text and vision cards. Meta-family models show `powered_by` as `Meta <label>`.

## Tests

`server/tests/test_meta_models.py` mocks the OpenAI client. It pins `VISION_PROVIDER=baseten` where needed so a Meta key in those tests still expects Baseten vision. It checks that Baseten-only env serves Muse Spark Open for text and vision, that a 403 is named in the log and in health without the key, that `VISION_FALLBACK_MODEL` is one extra call only for an access error, that a tiny drawing fails a positive match, and that a non-Meta id is still refused for text. `server/tests/test_vision_provider.py` covers the Meta vision default, `VISION_PROVIDER`, and `VISION_FALLBACK_PROVIDER=baseten`. Health tests cover vision-down/text-up (HTTP 200, `partial`) and text-down/vision-up (HTTP 503). `server/tests/test_owner_ai.py` covers the owner handshake, policy, and activity endpoints, including the keyword-rules path. `server/tests/test_text_provider.py` covers `LLM_PROVIDER`, `META_LLM_MODEL`, the Meta reasoning-effort retry, and the opt-in Baseten text fallback. No API key is required. From `server/`:

```bash
python -m unittest discover -s tests -v
```
